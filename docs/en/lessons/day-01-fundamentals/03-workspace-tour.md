## Why it matters

In someone else's Angular project the first questions are always the same: where is the entry point, where are the global providers, where are the routes. The structure is standard, so once you learn it you can find your way around any codebase.

## Concept

The files generated by CLI 22 (abridged):

| File | Purpose | Spring / React parallel |
|------|-------------|-------------------------|
| `angular.json` | workspace configuration: build/serve/test targets, assets, styles, budgets | `pom.xml` plugins / `vite.config.ts` |
| `package.json` | dependencies and npm scripts (`start` → `ng serve`) | the same |
| `tsconfig*.json` | TypeScript + `angularCompilerOptions` (strict templates) | `tsconfig.json` |
| `public/` | static files, copied into the build as is | `public/` in Vite |
| `src/index.html` | the single HTML page with `<app-root>` | `index.html` with `<div id="root">` |
| `src/main.ts` | entry point: `bootstrapApplication(App, appConfig)` | `main()` with `SpringApplication.run` / `createRoot().render()` |
| `src/app/app.config.ts` | global application providers (router and so on) | `@Configuration` class |
| `src/app/app.routes.ts` | route table | React Router route config |
| `src/app/app.ts` / `.html` / `.css` / `.spec.ts` | the root component `App`: class, template, styles, test | `App.tsx` |
| `src/styles.css` | global styles | `index.css` |

The startup chain:

```
index.html  →  <app-root></app-root>
main.ts     →  bootstrapApplication(App, appConfig)
app.config  →  providers: [provideBrowserGlobalErrorListeners(), provideRouter(routes)]
App         →  selector: 'app-root' → Angular renders the template in place of <app-root>
```

Pay attention to the names: since Angular 20 the CLI generates `app.ts` and the class `App`, not `app.component.ts` / `AppComponent`. In legacy projects you will see the old suffixes — that is only a naming convention.

> Caveat on the Spring analogy: `app.config.ts` does not scan the classpath. Providers are either listed explicitly, or a service declares itself available (details on Day 3).

## Follow along

1. Open `practice/src/index.html` and find `<app-root></app-root>`. Then open `src/app/app.ts` and find `selector: 'app-root'` — this is the link between the HTML and the component.
2. Open `src/main.ts`. This is the entire bootstrap: the root component + the configuration.
3. Open `src/app/app.config.ts`. Right now it has two providers: the global error listeners and the router with an empty `routes` array (`app.routes.ts`).
4. Open `package.json`. Note that there is **no `zone.js`** among the dependencies — Angular 21+ applications are zoneless by default (more on this in lesson 2.6). The test runner is `vitest` + `jsdom`.
5. Open `angular.json` and find `architect.build.options`: `browser: "src/main.ts"`, `assets` from the `public` folder, `styles`. Below it is `test` with the builder `@angular/build:unit-test`.
6. In the browser, open DevTools → Elements and expand `<app-root>`: the component's template is already rendered inside it.

## Try it yourself

Change the page `<title>` to `ParcelFlow Lite` and leave the document language as `en`. In which file is this done, and do you need TypeScript for it?

## Verify / Expected result

The browser tab shows **ParcelFlow Lite**. The change was made in `src/index.html`; no TypeScript code was needed.

## Common mistake / Best practice

**Mistake:** looking for `app.module.ts` or adding it "because the tutorial says so". **Consequence:** a mix of two architectures and unnecessary complexity. **Correct:** in a modern application the global configuration lives in `app.config.ts` through `provide*()` functions; NgModules are needed only to support legacy code (lesson 1.6).

## Interview checkpoint

**Q: How does an Angular application start?**

A: The browser loads `index.html`, which contains the root selector, typically `<app-root>`. The bundle runs `main.ts`, which calls `bootstrapApplication` with the root component and an application config holding global providers such as the router. Angular then instantiates the root component and renders its template into that element.

**Q: What is `angular.json` for?**

A: It is the workspace configuration: it defines projects and their build, serve and test targets — entry point, assets, global styles, budgets and per-environment configurations.
